# OdinDuo 2.0.0 — proposed stable release scope

Historical feature proposal prepared on 7 October 2026. The shipped scope and validation status are recorded in [the 2.0.0 release notes](../releases/2.0.0.md). This proposal also contains work that remains outstanding, including stock-device validation, reboot hardening and measured waiting-mode optimisation.

## Purpose

Make protection easier to understand, verify and troubleshoot while preserving the working Odin 3 + Retroid USB workaround. Existing Auto protect, protection after closing recents, Retry, Quick Settings, themes and diagnostics are the baseline rather than new 2.0 features.

The repository currently has no user issues. This proposal follows a source review and the physical 1.1 validation, including the failure notification being placed in Android's Silent section and the difference between observed doze/wake and independently verified deep sleep.

## Proposed features

| Priority | Feature | User benefit and scope |
| --- | --- | --- |
| Core | Dashboard 2.0 | A polished Material You overview with separate connection and protection status, session duration and the latest recovery. Dedicated, readable help and diagnostics replace long nested dialogs. Support portrait, landscape, large text and controller focus. Keep Protected tied to verified helper/USB state; do not imply that it proves current touch delivery. |
| Core | Guided first setup | A short flow for stock-service compatibility, notifications, Android background settings and adding the existing Quick Settings tile. Reuse the current setup checks, offer clear next actions, keep Auto protect opt-in and preserve existing users' settings on upgrade. |
| Core | Connection and wake test | An optional, bounded guided test for touches, screen-off/wake and reconnect. Show pass, fail or inconclusive results with actual input evidence where available. Prototype Retroid input detection on stock firmware before promising automatic verification; keep manual confirmation explicit if the Android display/input route cannot be observed. Do not store touch coordinates or monitor other input devices. |
| Core | Local session history | A readable, bounded timeline of connections, disconnects, recovery, stops and their reasons, plus session duration. Provide clear/export controls and a concise support summary. History/export failures must not interrupt protection. Preserve existing bounded diagnostics and redaction. |
| Core | Clear recovery alerts | Separate actionable failure notifications from the quiet ongoing service channel. Make recovery, setup and diagnostics easy to reach. Respect notification permission, blocked channels and user sound preferences; avoid repeated alerts for the same failure. The existing Retry cleanup guarantee remains essential. |
| Core | Boot and update recovery hardening | Validate startup after a real reboot, app replacement and long idle periods. Audit persisted restoration records and worker identity across boots, so old process IDs or old-boot snapshots cannot affect a replacement session/device. Never bypass unresolved restoration to launch a new guard. Android Force stop continues to require reopening the app. |
| Measurement-dependent | Leaner waiting mode and battery insight | Measure baseline overhead, then reduce redundant work while no Retroid is connected if physical tests show a benefit. Preserve prompt connection protection, health checking, immediate Stop and correct restoration. Report available whole-device battery readings honestly, not invented per-app drain or savings percentages. Keep CPU wake locks and wakeup alarms out of this design. |
| Secondary | Optional Dutch interface | Retain English as the default and offer Dutch through Android's per-app language support. Validate layout, notifications and service continuity during a language change. Keep support exports understandable independently of the interface language. |

## Implementation order

1. Prototype the guided input test, measure idle overhead, and audit reboot/upgrade restoration before committing to their implementation details.
2. Add structured local history and recovery alerts; make their failure modes independent of protection.
3. Build the dashboard and guided setup around those capabilities, then add the optional language.
4. Optimize waiting only where measurements justify it and rerun the connection/recovery checks after any guard change.

## Stable release checks

- Build and lint the release; require the existing protected-branch CI checks and meaningful policy/shell regressions for modified guard behavior.
- Test real stock Odin 3 start, Stop, recents dismissal, notification Retry, Quick Settings and repeated automatic detach/reconnect.
- Record touch after multiple screen-off/wake cycles and after reconnect. Report the observed power state accurately. Compare elapsed and awake uptime when investigating deep sleep; do not label doze alone as proven deep sleep.
- Test a real reboot and in-place upgrade from the public 1.1.0 APK, preserving Auto protect and appearance preferences without duplicate workers or premature cleanup.
- Test history bounds, concurrent service/UI activity, export redaction, large text, controller focus, both orientations and languages that ship.
- Compare waiting/protected/off workloads under matched conditions when reporting battery impact. Unsupported battery properties must appear as unavailable. Keep measurement uncertainty visible.

## Publication

Publish **v2.0.0 as a full stable GitHub release under Tufein**, with `prerelease=false` and the latest stable designation, after implementation and stock-device validation pass. Use the existing package and update-compatible signing certificate, a version code above 10, a non-debuggable APK and its SHA-256 checksum. Update the changelog, README, release notes and English Reddit fix post. Publish no GitHub beta or prerelease for this version; development candidates can be tested locally.

Brightness matching continues to use the Retroid hardware controls on the tested setup. Broader device/firmware support requires separate physical evidence before advertising compatibility.
