# OdinDuo 1.1.0-beta.2

This prerelease fixes two reliability problems found while reviewing beta.1 and makes failed protection easier to retry. **1.0.0 remains the stable release.**

- **Reliable status during busy sessions:** the helper atomically publishes its current power observation separately from the diagnostic log. Repeated log messages can no longer push the last successful sample outside the read window and stop a healthy session. Fatal errors and shutdown still override a healthy observation.
- **Recovery after failed restoration:** a missing session marker no longer bypasses cleanup. Retry first asks the previous helper to restore its saved USB settings, and replaces its script and log only after a successful acknowledgement. An older failure in the log cannot override a later confirmed Stop.
- **Visible failure and Retry:** if notifications are allowed, a stopped session with an error leaves an “OdinDuo needs attention” notification with **Retry protection**. The dashboard offers the same retry action. Starting protection clears the old failure notification after any previous cleanup finishes.
- **Current Quick Settings tile:** status changes request a native tile refresh, even when the panel is closed. The tile no longer runs a periodic polling loop and advertises toggle semantics for accessibility.

Includes the helper health checks, bounded automatic recovery, verified restoration and setup checks from beta.1.

Install `OdinDuo-1.1.0-beta.2.apk` over the existing app. The package and signing certificate are unchanged; version code is 9. A SHA-256 checksum accompanies the APK. **After upgrading, Stop protection once and re-enable Auto protect to load the new helper.** Existing sessions from older APKs remain compatible until stopped. Android may require uninstalling the beta before returning to stable 1.0.0; Stop protection before uninstalling.

## Validation

- Reproduced the log-overflow failure on the installed beta.1 in an isolated Android 15 emulator: its root helper remained healthy but the service stopped after the last power sample left the 32 KiB log tail. Beta.2 remained Protected with the same helper in the equivalent test.
- Java regression checks cover current observations with noisy logs, fatal-error/shutdown precedence, legacy heartbeat adoption, stale/future timestamps and malformed records. The real-shell lifecycle suite also checks WAITING and ACTIVE heartbeat observations across reconnects.
- Android emulator checks used a test-only PServer stand-in and temporary USB files. The tile followed app Start/Stop with its panel closed. An injected restoration readback failure retained snapshots, removed the marker and posted the Retry notification. A retry while restoration still failed preserved the old helper and could not start a new lease. After removing the injected fault, tapping the actual notification Retry action confirmed restoration, started a healthy session and cleared the failure notification. Final Stop restored all five original power controls.
- Release build and Android lint passed with zero errors. Five existing warnings remain for the vendor reflection API, target SDK, dependency/tool upgrades and an icon resource qualifier.

The new changes have not yet been tested with physical Retroid touch input. The emulator cannot establish sleep/wake touch reliability or stock-firmware compatibility for these changes. Existing physical workaround results apply to the earlier build. Battery impact and other firmware/device combinations remain unmeasured. Automatic brightness sync remains unavailable on the tested setup.
