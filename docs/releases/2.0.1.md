# OdinDuo 2.0.1 — development candidate

This maintenance update strengthens session recovery and the new 2.0 dashboard. The latest published full release remains [2.0.0](https://github.com/Tufein/OdinDuo/releases/tag/v2.0.0).

## Changes

- Session status and helper health must belong to the current Android boot. A previous session cannot appear running just because a process ID or elapsed timestamp is reused.
- New root-side sessions save the boot identity and worker start time. Previous-boot snapshots are retired without signalling processes or changing current USB settings. Invalid boot records remain pending. A delayed old watchdog cannot stop a replacement lease.
- Session duration follows Android elapsed time, including sleep, and survives a same-boot service restart. Changing the wall clock no longer changes the duration.
- Saved status messages and ongoing notification actions follow English/Dutch app language changes while protection continues.
- History stays bounded at up to 80 entries, 1,024 characters per event plus a truncation marker and 256 KiB of encoded data. Tokens are redacted. Lock contention and corrupt history cannot block protection indefinitely, and failed clearing is reported accurately.
- First-run setup waits for notification permission and a resumed activity, avoiding a delayed dialog after leaving the app.
- An unexpected helper or watchdog stop offers Retry after confirmed cleanup. It is no longer incorrectly reported as a disconnected display. Only a detach in the latest helper session counts as a normal manual-session end; automatic recovery remains bounded.

## Update

The candidate uses version code 21, the existing package `nl.retroid.touchguard`, and the public release's signing certificate. Stop protection before installing, then enable Auto protect again. An opted-in running 2.0.0 session is also restarted through the update receiver when Android delivers package replacement.

Legacy helpers do not contain the new boot metadata. Upgrading replaces them after the existing Stop/restore confirmation; the stronger boot-record guarantees apply to sessions created by 2.0.1. Unresolved restoration still prevents a new session.

## Validation

- Local debug, signed release and instrumentation builds pass. Both Android lint variants report zero issues. The release is non-debuggable, targets SDK 36 and retains the public signing certificate.
- Host regression checks pass for elapsed timing, owner loss/adoption, reconnection, restoration retry, invalid and previous-boot records, worker process-ID reuse and delayed-watchdog isolation. The reused-process test verifies that an unrelated test child remains alive.
- Android instrumentation passes history bounds (including escaped data), concurrent service/UI-style writers, token redaction, contention, corrupt-history recovery and persisted English/Dutch status.
- An isolated Android 15 emulator preserves the same root helper and elapsed session after a sticky service restart. Changing English/Dutch updates the running status and notification Stop action while the helper continues. Automatic detach/reconnect and confirmed Stop restore the fake USB chain.
- Installing the signed candidate over the exact public 2.0.0 APK resumes opted-in protection and preserves Dutch. The replacement session uses the new helper.
- A real emulator reboot rejects the old boot/session records. Protection recovers after restarting the test vendor service and requesting Retry. The stand-in is not an Android boot service, so this does not validate unattended stock-device Auto protect startup.
- First-run UI checks confirm that setup waits for notification permission, stays unseen when the activity is backgrounded before the delay, and opens after resuming.
- On stock Odin 3 Android 15 (`Odin3_V1.0.0.187_20260616_193307_user`), the signed candidate installs over 2.0.0 and preserves enabled automatic mode. A killed Android service adopts the same root helper and elapsed session. Actual recents dismissal leaves protection running; the dashboard Stop and Start actions work.
- The stock-device interruption test exposed an unexpected watchdog stop being labelled as a display detach. The fix reports helper loss after confirmed cleanup, displays the recovery alert and restores a new helper when its actual notification Retry action is pressed. Host regressions cover the captured watchdog trace, real detach, stale detach logs and restoration failures.

Emulator tests use fake USB files and a test-only stand-in for the privileged AYN service. They cannot establish physical Retroid touch delivery or stock-firmware startup behavior. CI results are recorded on the candidate pull request.

Physical Retroid touch after repeated sleep/wake and reconnect, and opted-in stock-device recovery after reboot, remain pending. Battery consumption and automatic brightness synchronization have not been measured or implemented in this update.

## Reproduce the storage and language tests

Use a disposable Android emulator with protection stopped. This suite clears the test installation's local history and status; it must not be run on an everyday installation. Its runner rejects non-emulator hardware.

```sh
./gradlew :app:assembleDebug :app:assembleDebugAndroidTest
adb -s YOUR_EMULATOR_SERIAL install -r app/build/outputs/apk/debug/app-debug.apk
adb -s YOUR_EMULATOR_SERIAL install -r app/build/outputs/apk/androidTest/debug/app-debug-androidTest.apk
adb -s YOUR_EMULATOR_SERIAL shell am instrument -w nl.retroid.touchguard.test/nl.retroid.touchguard.ReliabilityInstrumentation
```
