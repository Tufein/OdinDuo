# OdinDuo 1.1.0-beta.1

This prerelease improves detection of failed background protection and adds controls that are useful while gaming. **1.0.0 remains the stable release.**

- **Helper health:** fresh session heartbeats are required before showing Protected. Auto protect can recover a failed helper after confirmed restoration, with two attempts per 60 seconds of awake uptime. Deep sleep does not consume the recovery grace. Manual sessions stop with an error on helper loss.
- **Verified restoration:** successful sysfs writes are checked by reading back the original value. Failed reads, invalid snapshots and mismatched readback retain recovery data and prevent a successful Stop acknowledgement.
- **Quick Settings tile:** add it through Help & diagnostics → Check setup → Add quick tile. Tap to enable Auto protect or stop protection; long-press opens the dashboard. Locked devices require unlocking before toggling.
- **Setup checks:** inspect the stock AYN service, Android profile, notifications, background restrictions and battery optimisation; open Android app settings directly. The same checks are included in diagnostics.
- **Notification prompt:** changing the theme no longer repeats the initial permission request.
- **Readable help:** setup steps and explanations keep their paragraph breaks instead of being flattened into one long paragraph.

Install `OdinDuo-1.1.0-beta.1.apk` over the existing app. The package and signing certificate are unchanged; version code is 8. A SHA-256 checksum accompanies the APK. Android may require uninstalling the beta before returning to stable 1.0.0; Stop protection before uninstalling.

## Validation

- Java policy checks cover startup, silent helper loss, sleep grace and retry limits.
- Real-shell regression checks cover process ownership, restoration, three reconnects, failed restoration readback, retained snapshots and confirmed retry.
- Android 15 emulator checks used a test-only stock-service stand-in and temporary USB files. The native add-tile prompt, SystemUI start/wait/connect/stop, and original power restoration passed, including clicks while the tile was on another page. Killing both root helper processes without a shutdown log produced Recovering, confirmed restoration and automatic relaunch; a manual session ended with an error and restored power. Three unexpected graceful helper exits stopped the automatic session after two recoveries.
- Setup was inspected in landscape/light and portrait/dark layouts. The Android app-settings shortcut, notification denial followed by a theme change without another prompt, and local diagnostics export with setup checks and redacted session tokens passed.
- Release build and Android lint passed with zero errors; five existing warnings remain for the vendor reflection API, target SDK, dependency/tool upgrades and an icon resource qualifier.

The new changes have not yet been tested with physical Retroid touch input. Existing physical workaround results apply to the earlier build. Battery impact and other firmware/device combinations remain unmeasured. Automatic brightness sync remains unavailable on the tested setup.
