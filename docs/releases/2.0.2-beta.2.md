# OdinDuo 2.0.2-beta.2

This candidate adds a resumable introduction and connection troubleshooting to the dashboard feedback from beta.1, on top of stable 2.0.1. It leaves the USB guard and restoration protocol unchanged.

- **Getting started:** four scrollable steps explain compatibility, optional notifications, checking both displays, and manual versus automatic protection. The saved page survives interruption and activity recreation. Finish and Skip are separate choices; the introduction can be replayed from the dashboard. Navigation never starts protection.
- **Permission choice:** notification access is requested only by an explicit tap after explanation. Declining does not block setup. Later attempts open app settings after the initial permission request.
- **Screen connection help:** guidance is available even with protection stopped. For a black Odin display with Android visible on the Retroid, unplug first to recover the Odin view and inspect the firmware display settings. An external-only mode is a possibility, not a confirmed cause or a verified setting name.
- **Support evidence:** shared diagnostics include the firmware, capture time and the display IDs, validity, reported power states and active modes available through public Android APIs. No screenshots, display content, unique display IDs or display-setting changes are involved.
- **Request fixes:** a consumed Start intent cannot restart an old request after recreation; timed-out Auto protect changes explain that saving was not confirmed. A delayed introduction does not cover a manually opened setup check.
- **Connection checklist:** manual protection ends on detach. The reconnect check now asks for Auto protect or a new manual session, and unchecked items are described as unverified.

## Signing and installation

Version code is **23**. This candidate uses the same new private release key prepared for beta.1. Its signer SHA-256 is `eed6825524ba2bd056241dc5c98a94ce244dd93294a9701357d13f38261e5f96`.

It cannot update public stable 2.0.1 or earlier installations signed with the previous certificate. Before changing installations, tap Stop protection and wait for confirmed restoration. If restoration fails, keep that installation and use its recovery controls. After confirmed restoration, preserve diagnostics, uninstall the old app and install the new APK. Uninstalling removes settings and logs. A fresh install starts with Auto protect off.

Never include the private keystore or its password in a release or Git. Existing installations made with the new beta.1 signing key can update to this candidate.

## Validation and limits

- All 26 API 35 Robolectric host tests pass: 12 dashboard regressions, nine introduction/permission/navigation cases and five read-only display-report cases. Coverage includes interruption, rotation, manual replay, separate Finish/Skip, Dutch landscape content, consumed Start intents and delayed-introduction guards.
- The six Java regression programs and real-shell lifecycle suite pass.
- Debug and instrumentation APK builds pass. Debug and release lint each report zero errors and two upgrade-availability warnings (Android Gradle Plugin and a test dependency).

The instrumentation APK was compiled; its tests were not executed in this environment. These host checks do not establish physical panel behavior or Retroid touch/sleep reliability. Physical Odin validation remains required.

The reported main-display blackout has **not** been reproduced or fixed in this environment. Diagnostics are intended to distinguish Android-reported display policy from a physical panel/link failure.

VirusTotal has not scanned this candidate. The earlier APK upload was rejected by the managed credential integration; GitHub binary uploads also failed. No scan result or public APK publication is claimed until those operations succeed for this exact candidate.
